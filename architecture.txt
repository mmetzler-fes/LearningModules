================================================================================
  LearningModules – Architekturüberblick
================================================================================

STACK
-----
  Backend  : NestJS 11 (Node.js), alle Routen unter /api
  Datenbank: TypeORM + SQLite (data/database.sqlite), synchronize: true
  Auth     : Passport JWT, 24 h, Secret: JWT_SECRET env || 'secretKey'
  Passwort : crypto.scryptSync, gespeichert als "<salt>:<hash>"
  Frontend : Vanilla JS + HTML, kein Bundler

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
DATENFLUSS (Login → Quiz)
--------------------------------------------------------------------------------

  1. app.init()
       → LoginView.initLoginScreen()  (Admin-Toggle prüfen)

  2. Benutzer logt ein
       → LoginView.enterApp()
       → App.loadTopics()  +  App.loadExamMode()
       → App.setupNavigation()
       → App.navigateToView('teacher-dashboard' | 'student-topics')

  3. Lehrer öffnet Thema
       → TopicsView: Klick "Module" → ModulesView.openTopicModules(topicId)
       → API: GET /api/topics/:id/modules
       → ModulesView.refresh() → H5pRenderer.renderPreview()

  4. Schüler startet über einen Themen-Link
       → ?l=<token> → LoginView.startLinkEntry()
       → API: GET /api/public/link/:token   (Name, Modi, Passwortpflicht)
       → Name, ggf. Passwort, ggf. Modus wählen
       → API: POST /api/public/link/:token/start   (liefert die Module)
       → QuizView.startLinkRun() → _renderModule()
       → QuizView._finishQuiz()
       → API: POST /api/public/results (mit linkToken und mode;
              im Modus "Lernen mit Lösungen" entfällt das Speichern)

--------------------------------------------------------------------------------
ROLLEN
--------------------------------------------------------------------------------

  admin    Vollzugriff; sieht Admin-Nav (Benutzerverwaltung, Whitelist/Blacklist)
  teacher  CRUD eigene Themen, Module, Tags und Themen-Links; sieht Ergebnisse
           Eigentümer  = Schreibrechte am Inhalt (ändern, löschen, freigeben)
           Nutzer      = Benutzungsrechte: eigener Quick-/Themen-Link auf
                         fremde Inhalte, die Ergebnisse kommen zu ihm.
                         Freigaben lassen sich bei sich ausblenden oder
                         entfernen – beim Eigentümer ändert das nichts.
  student  Kein Konto und keine Anmeldung. Zugang ausschließlich über einen
           Themen-Link (?l=) oder Quick-Link (?q=); der Link ist der Schlüssel.
